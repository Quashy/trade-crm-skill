# 外贸客户与订单管理

将用户的业务意图落实为可在 Obsidian 中阅读、编辑的客户和订单资料。使用本地 Markdown 和附件保存资料，材料读取与理解由宿主模型完成。

## 先确定业务资料库

- 使用用户指定的资料库根目录；尚未指定且本会话没有选库记录时，先询问资料存放位置，再检索本地记录。同一会话复用已选目录，切换时重新定位客户和订单。
- 相对路径按当前工作目录解析并回显实际根目录；路径含义不明、不可访问或目录内容异常时，说明情况并询问。用户明确要求在指定位置初始化时，创建资料库并复制包内模板为根目录的 `模板.md`。
- 技能目录保存指令和模板，业务资料存放在用户另选的独立目录；个人路径保留在会话上下文中。

## 按需参考

- 收到截图、文件，或需要判断业务意图、对象、信息取舍时，读取 [材料接收与决策](references/intake.md)。
- 查询或写入客户、订单及附件时，读取 [资料维护流程](references/workflows.md) 中相关部分。
- 需要理解省略表达、澄清方式或业务结果示例时，读取 [操作示例](references/examples.md)。
- 新建文档优先读取资料库中的 `模板.md`；缺失时使用 [包内模板](assets/模板.md)。已有模板异常时先询问。

## 核心流程

1. **理解请求。** 结合用户消息、客户或订单上下文及模型对材料的理解，判断查询、整理、新建或更新操作。用户消息确定业务动作，材料提供业务信息。
2. **读取相关记录。** 在选定资料库内按客户 ID、名字、公司、联系方式和业务线索检索，读取候选客户及订单原文。
3. **确定目标。** 客户 ID 是唯一标识；订单用“客户 ID＋订单号”定位，结合其他线索判断业务关联。
4. **处理决策。** 意图和目标明确、信息充分时直接处理。用途或归属不明、存在实质冲突或意外情况时，按材料接收流程给出依据、选项和建议，等待用户决定后再写入相关内容。
5. **维护资料。** 按资料维护流程最小范围修改，保留历史报价、用户手工内容及原始附件。未知资料标为“待补充”，未确认方案保留在待确认事项，不自动转成最终确认结果。
6. **核对结果。** 回读受影响文档，检查客户归属、编号、摘要、状态、日期和链接，说明已完成变更及仍待处理的事项。

## 完成条件与回复

- 查询：返回所问信息及来源文档、章节，标注未找到、未确认或冲突内容。
- 写入：目标文档和客户订单目录一致，涉及的附件存在且链接可解析；不相关内容保持原样。
- 澄清：列出实际候选、差异或受影响文件，提供可行选择和建议理由。
- 默认使用简体中文，简述操作对象、已完成变更、结果路径和仍待用户决定的事项。说明结果路径时使用宿主支持的可点击文件链接。

## 功能范围

负责本地客户与订单资料的新增、查询和更新；删除不在本技能范围，外部系统录入及 Git、Obsidian 同步由用户现有流程处理。
