# 资料维护流程

## 存储与模板

以下为选定资料库内的结构示例，根目录名称由用户选择。

```text
客户管理库/
├── 模板.md
└── 123-德国-Alex/
    ├── 客户.md
    ├── R-001.md
    └── R-001/
        ├── 报价-v1.xlsx
        └── 设计稿.pdf
```

优先使用资料库的 `模板.md`，缺失时使用包内 `assets/模板.md`。模板包含客户和订单两部分，新建时取对应部分，保留原模板。

沿用模板的字段、章节和相对链接。新客户的订单目录从空表开始；生成业务文档时填写模板占位符，未知资料填写“待补充”，外部订单号缺失填写“未提供”，空章节可留空。

业务目标路径解析到选定资料库内，附件来源可在库外。按目标文件系统核对文件名；名称无效或有路径冲突时，建议可用名称并请用户选择。

## 查询

先通过客户 ID、名字、公司或业务关键词缩小范围，再读取客户文档及相关订单原文。客户摘要用于导航，订单详细信息以对应订单文档为准。

返回所问内容及来源章节。例如查询“报价和箱规”，分别查阅“报价与商务条件”和“包装、箱规与装箱”。有多个版本时区分历史、待确认和最终确认结果；查无记录时说明结果。

## 客户建档与修改

1. 新客户需要用户提供的数字 ID、国家和名字。ID 按原始数字字符串保存，包括用户原本提供的前导零；不自动编号、不加 `C`、不额外补零。
2. 检索整个选定资料库中的该 ID，包括目录和客户文档。已有该 ID 时不重复建档；目录与文档 ID 不一致时先请用户决定。
3. 按 `客户ID-国家-名字/客户.md` 建档。客户 ID 不限制位数；新建时只写已明确的客户资料、备注和跟进事项。
4. 修改联系方式等已有字段时保留其他资料；与现值存在未解释冲突时先询问。用户明确要求更换并提供新值时执行，并保留有业务价值的旧信息或变更说明。
5. 用户要求修改国家或名字时，客户 ID 保持不变。检查目标目录及受影响链接；无重名、路径或归属冲突时同步修改目录、客户字段、订单显示信息和实际受影响链接。

日期采用用户指定或宿主提供的会话时区，格式 `YYYY-MM-DD`。保留建档日期，有业务变更时更新“最近更新”；历史业务日期按材料来源另行记录。

## 新建询价与订单编号

首次询价或需求沟通即可建单，无需成交或外部订单号。先确定这是一笔新业务，避免对同一业务反复建单。

在该客户下，综合读取：

- 形如 `R-数字.md` 的订单文档；
- 形如 `R-数字/` 的附件目录，即使目录为空也计入已占用号；
- `客户.md` 订单目录中已列出的订单号。

按数字值取最大值加一，数字部分至少三位：无已用号时为 `R-001`；存在 `R-001`、`R-003` 时下一号为 `R-004`；`R-999` 的下一号为 `R-1000`。不同客户分别编号，不按字符串排序，不填补空号，不对既有订单重新编号。发现目录表与文件不一致、异常编号或重复编号时，先说明异常并请用户决定，不能把异常当作空库。

写入前核对新编号是否可用，存在占用或记录异常时先询问。建立 `R-XXX.md` 和同级 `R-XXX/`，再更新客户订单目录。新询价默认状态“询价中”，用户已明确其他状态时按用户信息记录。

发现历史资料被手工移走或删除的迹象时，请用户确认下一编号。

## 订单更新与摘要同步

同一笔业务从询价到成交持续维护相同文档及附件目录，不因状态变化或取得外部订单号改名。

| 业务内容 | 记录位置 |
|---|---|
| 产品、数量、规格、材质、颜色、LOGO、定制要求 | 产品需求与定制 |
| 各版报价、议价、费用、付款、收款、交期 | 报价与商务条件 |
| 独立包装、标签、箱规、重量、装箱方式 | 包装、箱规与装箱 |
| 运输方式、货代、运费、提货和物流进展 | 发货与货代 |
| 重要沟通和变更的时间、依据、过程 | 沟通与变更记录 |
| 未决问题、备选方案、后续动作 | 待确认与下一步 |
| 明确确认的方案和结果及对应依据 | 最终确认结果 |
| 实际存在的附件、说明和链接 | 附件目录 |

按相关章节局部修改，保留手工增加的章节、备注和仍需留档的历史。多个事项可分配到对应章节，沟通记录只保留理解变更所需的过程，不重复抄写整份材料。

报价以版本追加，保留币种、单位、适用数量及明确的商务条件；没有提供的内容保持待补充。用户要求保留第一版、增加第二版时，追加第二版并说明当前确认情况，不覆盖第一版。不能从一张生产单的存在推断“已成交”，也不能把讨论方案写成最终结果。

用户明确说“已成交”等状态变化且目标唯一时，更新订单状态、更新时间及客户订单目录对应行；不自行增加其他状态流转。写入最终确认结果需有明确确认依据，不将所有待确认事项一次性勾成完成。

客户订单目录每个订单只保留一行，包含订单号、简短业务摘要、当前状态、最近更新和文档链接。订单文件和订单目录对应行保持一致；客户基本信息的“最近更新”同步为本次业务更新日期。查询不更新这些日期。

## 附件归档与链接

业务归属确定后，按用户的归档或资料维护要求，将原件复制到对应 `R-XXX/`。仅供阅读的附件按阅读任务处理；客户层面材料的放置位置由用户决定。

附件保留有业务意义的文件名，例如 `报价-v2.xlsx`。同名时按材料接收流程确认版本和归档名称。复制后核对归档文件，保留原始文件及内容。

使用相对 Markdown 链接：

- 客户文档指向订单：`[查看订单](R-001.md)`。
- 订单指向客户：`[Alex](客户.md)`。
- 订单指向附件：`[报价第一版](R-001/报价-v1.xlsx)`。

路径分隔符使用 `/`，文件名中的空格、`#`、括号等字符应在链接目标中正确编码，显示名称保留可读文本。相对路径从链接所在文档计算，不只根据文件名推测。附件目录记录文件含义、已知版本及必要的来源信息；有本地原件就链接归档副本，仅会话可见的材料如实注明来源，不能制造本地文件链接。

## 写入完成检查

按以下顺序核对本次实际影响范围：

1. 目标客户和订单与用户选择一致；新文件无占用冲突。
2. 文档内容和日期正确，历史资料及手工内容保留，生成文档没有残留模板占位符。
3. 客户目录行与订单号、摘要、状态、日期一致；状态变化没有改动订单编号。
4. 本次新增、修改的所有链接都解析到真实目标，附件归档完成。
5. 回读写入结果，报告实际完成范围；出现变化、冲突或部分失败时按材料接收流程交由用户决定。
