# 材料接收与决策

收到阿里巴巴聊天截图、报价单、生产单或其他业务材料时，按本流程判断业务动作。直接使用宿主模型对材料的理解，不建立额外提取管线、字段结构或识别置信度评分。

本流程的本地检索、候选比对和写入，都以入口中已确定的业务资料库为范围。尚未选库时可理解用户提供的材料，但先询问资料存放目录，再检索本地记录；不能从截图、附件或技能安装位置推定资料库。纯阅读请求无需选库。

## 先判断用户要做什么

结合本轮消息与已明确的上下文：

- 用户已说“更新客户 123 的 R-001”，材料用于这笔操作；目标可验证、内容清楚且无冲突时直接维护资料。
- 上文已明确某笔订单，随后说“再加上这份包装要求”，可以沿用该对象，但写入前仍需读取本地原文。
- 用户只提供材料，但上下文已明确正在给某客户建档或更新订单，可继续同一操作。
- 用户只发材料且没有明确用途，先只读整理，提出可能的业务操作，再询问用户；“收到了附件”本身不是新建或更新的授权。
- 用户只要求翻译、阅读或总结，就完成该要求，不扩大为建档、归档或状态更新。

材料无法读取、缺页、文字模糊或关键信息不可确定时，准确说明无法判断的内容及其影响，询问用户补充、澄清或选择是否只保留已明确部分。不要猜写电话号码、价格、币种、数量、单位和交期。

## 再判断归属及新建、更新

在相关本地记录中比较客户标识和业务线索，不从文件名或显示名称直接下结论。

| 情况 | 处理 |
|---|---|
| 客户 ID 与本地记录一致，其他资料无冲突 | 以该客户为候选，继续核对订单 |
| 同名客户有多个，或联系方式与已有客户不同 | 展示候选及差异，请用户指定；不自行合并 |
| 没有匹配客户且用户要建档 | 请求用户提供数字 ID、国家、名字；不能从平台账号生成客户 ID |
| 客户明确，但新询价与旧订单补充均合理 | 展示相关订单摘要，询问“新建询价”还是“更新哪笔订单” |
| 只有订单号，多个客户下均有此编号 | 结合明确上下文定位；仍不能唯一确定时询问客户 |
| 多份材料涉及多个客户或订单 | 先说明分组判断；归属不清的材料留待用户决定 |

只有材料而缺少明确操作指示时，即使未匹配到记录，也先报告检索结果及建议，不因“未搜索到”就自动创建客户或订单。用户已明确要求新建、必填信息充分且无冲突时，按维护流程直接建档。客户 ID 重复、同一 ID 对应多个目录时，暂停相关写入并请用户决定。

## 冲突与不确定信息

先区分正常业务变化与尚未解释的矛盾：

- 用户明确说“第二版报价，保留第一版”，按追加版本处理；版本变化不等于必须再次询问。
- 材料清楚呈现了已确认的变更，且用户已要求更新该订单，可记录变更及对应依据，保留原记录。
- 聊天、报价单、生产单或本地记录存在未解释的价格、数量、规格、包装或状态差异，交给用户决定，不自动选最新文件、最后上传项或某一种材料。
- 用户或客户提出“能不能”“考虑”“先按这个看看”等方案，不表示最终确认。无法确定是否确认时询问，或按用户要求仅记为待确认方案。
- 截图上传顺序、文件修改时间、文件名里的“最终”不足以单独证明业务先后或最终有效性。

对每个阻止写入的决定，说明：

1. 问题：哪笔业务的哪项信息存在疑点。
2. 依据：现有文档及材料分别写了什么，尽量指出附件名、页码、工作表或截图日期等已有定位线索；没有明确定位信息就如实说明。
3. 选择：例如采用某项并留档旧值、两种方案都记为待确认、暂不写入。
4. 建议：推荐哪种做法及原因；建议不代替用户选择。

将同一次操作中相关的疑点合并询问，减少来回。等待期间可以继续阅读、整理证据，受影响的正文、摘要和附件归档均暂缓。用户已作出的明确决定在当前操作中持续有效。

示例：

> 客户 123 的 R-001 当前记录为 1,000 个，报价单为 2,000 个；截图没有明确确认数量变更。可以采用 2,000 个并保留变更记录，也可以先把 2,000 个记为待确认方案。我建议先记为待确认，避免生产按未确认数量执行。你希望如何处理？

## 意外情况

- 同名附件：列出现有文件与待归档文件，询问是同一版本、另存新版本还是暂缓；即使用户要求归档，也不覆盖现有文件。
- 只有会话截图、没有可复制的本地原件：可以依据已理解内容处理已授权的文字记录，标明来自本轮聊天截图；若需要归档原图，说明尚未归档并询问原件位置或处理方式，不制造不存在的附件链接。
- 关联资料或章节缺失、文件不可写、目录重名或存在同步冲突：说明异常和可选修复办法，由用户决定是否修复及采用何种内容，不自动大范围重建资料。
- 部分写入失败：核实磁盘实际结果，说明已写入、未写入和不一致之处；暂停依赖步骤并给出补齐建议，等待用户决定。不要通过删文件、重编号或覆盖整份文档来掩盖失败。

用户决定后再读取目标最新内容，按选择修改，并在业务变更记录中保留必要依据。只记录这次业务所需的决策，不将一次选择提升为所有未来订单的默认规则。
