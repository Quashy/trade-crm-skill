# 操作示例

示例中的 ID、材料及业务值只是说明，实际操作以用户提供的信息和本地记录为准。

## 首次选库与切换

- 首次说“新建客户，ID 123，德国，Alex”，但尚未选库：先询问资料库根目录；选定后在本会话复用。
- 用户说“换到另一个业务员的资料库”：选定新根目录后，重新检索客户与订单。
- 用户给出的目录不存在：说明情况，询问实际位置或是否在该位置初始化。

下列业务维护示例均以已明确选库为前提；目录未确定时先完成选库。

## 明确的自然语言请求

| 用户表达 | 处理与结果 |
|---|---|
| 新建客户，ID 是 123，德国，Alex。 | 检查 ID 无冲突后，建立 `123-德国-Alex/客户.md`；其他未知资料待补充，订单表不放占位订单 |
| 给客户 123 补充联系电话。 | 未给号码且材料中也无明确号码时，询问具体号码，不写入猜测值 |
| 客户 123 的电话补充为 +49 30 123456，原来没有。 | 读取最新客户文档，填写联系方式和最近更新，保留其他内容 |
| 客户 123 有一笔新的卡册询价，帮我建立记录。 | 分配该客户下一订单号，建立订单文档与附件目录，在客户文档加入摘要行 |
| 客户 123 的 R-001 需要独立包装。 | 更新包装章节及相关摘要、日期，不自动增加报价或确认成交 |
| 给 R-001 记录第二版报价，第一版保留。 | 有明确当前客户上下文且提供了第二版内容时追加；多个候选或缺少报价内容时先问 |
| 查一下客户 123 的 R-001 报价和箱规。 | 从订单原文相应章节回答，区分各版报价和未确认内容，给出来源，不修改资料 |
| 客户 123 的 R-001 已经成交。 | 同步订单及客户目录状态、日期，编号与附件目录保持不变 |

## 截图和文件驱动

### 上下文已经明确

上文：“接下来更新客户 123 的 R-001。”

用户发送聊天截图和报价单：“这次报价定了，按这份补充进去，旧版留着。”

模型理解材料后读取本地订单。最终确认、版本及业务内容清楚时，直接追加报价、记录确认依据并维护摘要，按本次归档要求保存附件。

### 只有材料，没有用途

用户发送几张阿里巴巴聊天截图和一个报价文件，没有其他说明；此前没有当前客户或业务上下文。

先整理材料并在已选资料库中检索候选。例如：“材料中的公司与客户 123 接近，但还不能确定是 R-001 的后续沟通还是新询价。建议先确认业务归属。你希望补充到 R-001，还是建立一笔新询价？”用户选择后再处理。

### 新客户缺少 ID

用户：“这是德国 Alex 的聊天，帮我建档。”

未查到相符客户，用户也未提供 ID。说明未查到的结果，请用户提供数字 ID；不能用阿里巴巴账号、联系电话或自动生成数字代替用户指定 ID。

### 客户明确，订单不明确

客户 123 已有两笔卡册业务，材料没有本系统订单号。

列出两笔订单的编号、摘要及相关差别，询问补充哪一笔或新建一笔。同产品、同数量或同一天不自动视为同一订单。

### 材料与本地记录冲突

R-001 记载 1,000 个，聊天出现 2,000 个，生产单仍为 1,000 个，均无明确确认变更说明。

列出差异和来源，建议先列为待确认，请用户决定采用值或暂缓；等待期间不改订单数量，不以生产单或最近上传的截图自动覆盖其他记录。

### 文件名相同

订单附件目录已存在 `报价单.xlsx`，用户又提供同名文件要求归档。

说明目标已存在，建议确认新版后另存 `报价-v2.xlsx`；由用户决定版本及归档名称，保留已有附件。

### 材料无法读取

用户要求按截图更新单价，但数字模糊。

说明具体单价无法辨认，询问明确单价或是否暂缓该项，同时继续整理可读信息。

## 阅读材料

- “翻译这张阿里巴巴聊天截图”：按请求提供翻译。
- “这份生产单写了什么”：只阅读和回答，不推断成交状态或自动写库。

## 用户手工编辑和部分失败

已有订单新增了“客户特殊备注”章节。补充包装要求时局部修改相关章节，保留特殊备注；客户订单表只同步对应行。

若订单已写入但客户文档写入失败，报告实际状态：“R-001 的包装要求已更新；客户订单目录尚未同步，当前仍是旧日期。”说明原因和补齐建议，请用户决定后续处理。
